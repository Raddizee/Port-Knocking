🛠️ Tutorial Konfigurasi Port Knocking pada MikroTik

Tutorial ini menggunakan RouterOS dengan mekanisme firewall address-list. Prinsipnya, setiap tahapan knocking memasukkan IP sumber ke daftar sementara. Jika urutannya benar, IP tersebut masuk ke daftar secured dan memperoleh akses.

1. Tentukan urutan Port Knocking

Sebagai contoh, gunakan urutan:

547 → 879 → 47

Timeout dibuat singkat, misalnya 30 detik, sehingga client harus menyelesaikan urutan dalam waktu tersebut.

2. Buat rule Knock pertama

/ip firewall filter
add chain=input protocol=udp dst-port=547 \
    in-interface-list=WAN \
    action=add-src-to-address-list \
    address-list=knock1 \
    address-list-timeout=30s

Saat client mengirim koneksi UDP ke port 547, IP sumbernya dimasukkan ke knock1.

3. Buat rule Knock kedua

/ip firewall filter
add chain=input protocol=udp dst-port=879 \
    in-interface-list=WAN \
    src-address-list=knock1 \
    action=add-src-to-address-list \
    address-list=knock2 \
    address-list-timeout=30s

Rule ini hanya berlaku untuk IP yang sebelumnya sudah berhasil melakukan knock pertama.

4. Buat rule Knock ketiga

/ip firewall filter
add chain=input protocol=udp dst-port=47 \
    in-interface-list=WAN \
    src-address-list=knock2 \
    action=add-src-to-address-list \
    address-list=secured \
    address-list-timeout=30m

Jika ketiga tahapan benar, IP client dimasukkan ke secured selama 30 menit.

5. Izinkan akses SSH/SFTP

Jika layanan SSH/SFTP berada pada MikroTik:

/ip firewall filter
add chain=input protocol=tcp dst-port=22 \
    in-interface-list=WAN \
    src-address-list=secured \
    action=accept

Rule accept ini harus berada sebelum rule drop WAN yang menutup akses masuk.

6. Jika SSH/SFTP berada di server LAN

Misalnya server memiliki IP 192.168.10.129. Maka selain firewall, diperlukan destination NAT (dst-nat) untuk meneruskan koneksi ke server:

/ip firewall nat
add chain=dstnat protocol=tcp dst-port=22 \
    src-address-list=secured \
    action=dst-nat \
    to-addresses=192.168.10.129 \
    to-ports=22

Kemudian pastikan firewall forward mengizinkan koneksi dari secured menuju server tersebut.

Alur keseluruhan

Client
   │
   ├── UDP 547 ──→ knock1
   ├── UDP 879 ──→ knock2
   └── UDP 47  ──→ secured
                         │
                         ↓
                  Akses TCP 22
                         │
                         ↓
                 192.168.10.129
Catatan: Contoh port 547 → 879 → 47 mengikuti ilustrasi yang digunakan. Dalam penerapan nyata, port knocking sebaiknya dipadukan dengan autentikasi SSH yang kuat dan aturan firewall lain — Port Knocking merupakan lapisan tambahan, bukan pengganti autentikasi.
